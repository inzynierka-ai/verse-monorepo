Jakub Ciepły

Czym jest Verse?

Nieskończona, oparta na postaciach tekstowa przygodówka napędzana LLM.

  • Gracz definiuje świat (statek kosmiczny, średniowiecze, szkoła...)
  • AI generuje sceny, lokacje, NPC, obrazy
  • NPC pamiętają wcześniejsze rozmowy
  • Relacje ewoluują w oparciu o dialog
STACK TECHNOLOGICZNY
  • FastAPI · backend w Pythonie
  • React + Vite · frontend
  • PostgreSQL + pgvector · baza danych i vector store
  • OpenAI / OpenRouter · LLM
  • ComfyUI · generowanie obrazów
  • Langfuse · obserwowalność

Atom: wywołanie LLM

Każda aplikacja AI jest z tego zbudowana.

  • Wiadomość systemowa — rola, zasady, format
  • Wiadomość użytkownika — właściwe zapytanie
  • Model, temperature, max_tokens
  • Narzędzia (opcjonalnie) — schematy funkcji
  • Wyjście: tekst, ustrukturyzowany JSON lub wywołanie narzędzia
response = await client.chat.completions.create(
  model="gpt-4.1-mini",
  messages=[
    {"role": "system",
     "content": "You are a character designer..."},
    {"role": "user",
     "content": "Story: cyberpunk... Describe: a hacker"}
  ],
  temperature=0.7,
  tools=[generate_location, generate_character],
)

Dwa kształty systemów AI

Workflow

Stały pipeline wywołań LLM. Projektujesz każdy krok.

  • Przewidywalny, testowalny, tani w debugowaniu
  • Dobry gdy znasz kroki z góry
  • W Verse: generowanie postaci i lokacji
Agent

Pętla LLM wybierająca kolejne narzędzie do wywołania, aż do zakończenia.

  • Elastyczny, radzi sobie z otwartymi zadaniami
  • Trudniejszy do przewidzenia, debugowania i ograniczenia kosztów
  • W Verse: generowanie scen

Trend w branży: przesunięcie w stronę agentów — ale płacisz za to złożonością.

Workflow: generowanie postaci

Każdy krok to małe, ukierunkowane wywołanie LLM.

    calls = extract_function_calls(response)

Wybór modelu: nie sięgaj od razu po największy

Dopasuj model do trudności kroku, nie do ważności aplikacji.

ZadanieUżyty modelDlaczego
Agent sceny (planowanie + użycie narzędzi) gpt-4.1 Wymaga rozumowania i wyboru narzędzi
Rozmowa z NPC gpt-4.1 Spójność głosu, długi kontekst
Ekstrakcja JSON postaci gpt-4.1-mini Ustrukturyzowane, dobrze zdefiniowane zadanie
Szkic postaci z opisu gemini-2.0-flash-lite Malutkie, szablonowe zadanie — szybko i tanio

Zasada: różnica kosztów 5–10× między poziomami. Schodź niżej, gdzie tylko się da.

Prompt engineering

  • Najpierw rola — "Jesteś generatorem scen..."
  • Sekcje w tagach — <persistence>, <planning>, <tool_usage>
  • Jawny format — "Zwróć wyłącznie poprawny JSON"
  • Konkretne ograniczenia — "1-3 postacie", "250–300 słów"
  • Negatywne reguły — "NIGDY nie modyfikuj postaci gracza"
<persistence>
Keep going until the scene is
complete. Only terminate when you
have a location, 1-3 characters,
and a description.
</persistence>

<planning>
Plan before each action. Think
about how this scene connects to
previous scenes...
</planning>

Cache promptów: darmowy zysk na latencji i koszcie

Dostawcy cache'ują prefiks twojego promptu. Jeśli pasuje między zapytaniami, dostajesz ≈ 50–90% zniżki na te tokeny i niższą latencję.

  • Umieszczaj stałą zawartość na początku (system prompt, schematy narzędzi)
  • Potem wolno zmieniający się kontekst (świat, postać)
  • Zmienną turę użytkownika daj na końcu
  • Nie wrzucaj kluczy ani znaczników czasu do prefiksu

Dlaczego NPC potrzebują RAG

Problem:

NPC w scenie #7 powinien pamiętać, co wydarzyło się z graczem w scenie #2.

Naiwne podejście: wrzuć wszystko do promptu. Szybko się wywraca — koszt i okno kontekstu.

Rozwiązanie: RAG

Retrieval-Augmented Generation.

Pobierz tylko istotne wspomnienia i wstrzyknij je do promptu w momencie odpowiedzi.

Czym jest embedding?

Wektor (~1536 floatów) uchwytujący znaczenie. Podobne teksty → bliskie wektory.

Trzy semantyczne sąsiedztwa w przestrzeni wektorowej: średniowiecze · sci-fi · dzicz.

Langfuse: jeden dekorator, pełny trace

@observe(name="generate_completion", as_type="generation")
async def generate_completion(self, messages, model, temperature, ...):
    langfuse_context.update_current_trace(metadata={
        "model": model.model_id,
        "provider": model.provider.value,
        "temperature": temperature,
    })
    response = await client.chat.completions.create(...)
    langfuse_context.update_current_observation(usage=response.usage)
    return response.choices[0].message.content

Zagnieżdżone wywołania @observe budują drzewo. generate_scene → agent_loop → generate_location → generate_completion.

Co właściwie zawiera trace

Per wywołanie LLM
  • Model i dostawca
  • Wiadomości wejściowe i system prompt
  • Tekst wyjściowy / wywołania narzędzi
  • Tokeny: prompt / completion / razem
  • Czas trwania
  • Błędy, ostrzeżenia (np. moderacja)
Per sesja / trace
  • ID użytkownika / sesji
  • Pełne zagnieżdżone drzewo wywołań
  • Zagregowany koszt
  • Własne metadane (krok, violated_categories, ...)
  • Oceny (ręczne lub LLM-as-judge)

Efekt: jeden bug typu "zła scena" → widok trace'a → dokładne wywołanie narzędzia → dokładny prompt, który to wywołał.

Wnioski

  1. Zaczynaj od atomu. Aplikacja AI to wywołania LLM złożone kodem.
  2. Najpierw workflow. Po agentów sięgaj dopiero, gdy problem jest naprawdę otwarty.
  3. Agent = pętla + narzędzia + stan. Zabezpieczenia trzymaj po swojej stronie: max steps, walidacja, typowany stan.
  4. Daj LLM pamięć przez RAG. Embeddingi + vector DB > upychanie kontekstu.
  5. Instrumentuj wszystko. Langfuse (lub odpowiednik) od pierwszego dnia.
  6. Dobieraj modele per zadanie. 80% wywołań prawdopodobnie nie potrzebuje flagowca.
  7. Struktura promptów — i taka, która pozwala na cache.
